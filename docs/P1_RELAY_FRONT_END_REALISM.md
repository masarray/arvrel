# P1 relay front-end realism

P1 relay front-end realism makes the virtual relay behave less like a protection equation fed by perfect phasors and more like a numerical relay with finite acquisition and binary-output behavior.

## Signal path

```text
virtual test set
  -> analog wire
  -> relay terminal
  -> input range / clipping
  -> ADC sample-and-hold
  -> ADC quantization
  -> measurement/filter group delay
  -> protection engine
  -> pickup / trip logic
  -> relay BO operate delay
  -> deterministic contact bounce
  -> virtual binary wire
  -> test-set BI debounce
  -> external pickup / trip timestamp
```

The protection engine still owns protection logic and internal operation evidence. The virtual test set still owns external timing and stop decisions from TESTSET.BI1/BI2 only.

## Analog front-end profile

`VirtualRelayFrontEndProfile` defines:

- ADC resolution in bits;
- current full-scale RMS;
- voltage full-scale RMS;
- ADC sample rate;
- fixed measurement/filter group delay;
- quantization enable;
- clipping enable.

The desktop default is a generic numerical-relay profile:

- 16-bit equivalent ADC magnitude grid;
- 20 A RMS current full scale;
- 300 V RMS voltage full scale;
- 4 kHz acquisition;
- 1.5 ms group delay;
- quantization enabled;
- clipping enabled.

These values are behavioral defaults for the generic virtual relay. They are not a certification claim for a named manufacturer or device.

## Timing semantics

The laboratory clock remains 4 kHz / 0.25 ms.

A delayed measurement is delivered to protection with the **current laboratory timestamp** but with values acquired earlier. This preserves protection timer progression while modeling the fact that a real relay makes decisions on filtered/processed measurements that lag the physical terminal waveform.

This creates two intentionally different timing domains:

1. **relay internal timing** — pickup/trip evidence generated by protection after the analog front-end delay;
2. **test-set external timing** — BI timing after relay output-contact delay, bounce, wiring and binary-input debounce.

An external trip time should therefore normally be later than the relay's internal trip timestamp.

## Clipping and quantization

Clipping is applied per configured relay input channel before protection sees the measurement. A test set may command a value above pickup while the relay remains below pickup because its virtual input full scale is lower.

Quantization maps RMS magnitude to a deterministic ADC-equivalent grid. Angle is preserved by reconstructing the phasor with the quantized magnitude.

The runtime records cumulative clipping and quantization counts for evidence.

## ADC sample-and-hold

The front end supports sample rates that are exact divisors of the 4 kHz simulation authority. Between acquisition instants the relay receives the last released measurement value.

This means fast source changes are not necessarily visible to protection immediately, even when the simulation itself continues at 0.25 ms resolution.

## Binary-output realism

`VirtualRelayContactProfile` now supports:

- pickup output operate delay;
- trip output operate delay;
- release delay;
- contact bounce duration;
- deterministic bounce period;
- test-set binary-input debounce.

The legacy `NumericalRelayDefault` profile keeps the original P0 behavior for regression compatibility. The desktop uses `RealisticNumericalRelay`, which adds 1 ms deterministic contact bounce and 0.5 ms BI debounce on top of the existing pickup/trip contact delays.

## Black-box invariant

Relay output bounce and test-set debounce do not weaken the P0 separation rule.

The injector must never stop because `ProtectionSnapshot.TripLatched` is true. It may stop only after the modeled relay BO signal crosses the connected virtual wire and the test-set BI accepts a stable rising state.

Disconnecting BO1 -> BI1 must still make the test set blind to relay trip.

## Evidence

Closed-loop evidence schema 6 adds:

- relay front-end profile;
- front-end profile fingerprint;
- front-end runtime snapshot;
- clipping count;
- quantization count;
- raw relay BO contact state;
- debounced TESTSET BI state;
- contact bounce/debounce profile.

This allows a measured time to be explained from the actual simulated acquisition and I/O path rather than from protection settings alone.

## Acceptance contract

P1 relay front-end realism is accepted when:

1. input clipping can prevent protection pickup even when injector output is above the protection setting;
2. quantized relay measurements lie on the configured deterministic ADC grid;
3. reduced ADC sample rate produces sample-and-hold behavior;
4. measurement group delay keeps the previous measurement authoritative until delayed data becomes available;
5. relay internal trip occurs later with a delayed front end than with the ideal front end;
6. external TESTSET.BI trip includes BO operate delay, contact bounce settling and BI debounce;
7. auto-stop still occurs only from the debounced wired TESTSET.BI1 edge;
8. the legacy ideal/compatibility profiles preserve existing P0/P1 regression behavior;
9. evidence identifies the exact front-end and contact profiles used.

## Safety boundary

This remains a deterministic virtual laboratory model. It does not model insulation, burden heating, transformer transient accuracy class compliance, anti-alias filter transfer functions, manufacturer-specific ADC architecture, physical relay output contact ratings, or hardware certification behavior unless a future device profile explicitly adds and validates those characteristics.
