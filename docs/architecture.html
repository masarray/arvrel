System design

Separate reusable IEC 61850 primitives from relay-specific decisions.

ARVREL owns the virtual-relay application, measurement context, trust policy, protection algorithms, and evidence presentation. The sibling ARIEC61850 repository remains the reusable frame, SCL, Sampled Values, and Npcap engine.

Repository boundary

Two repositories, one explicit responsibility split.

ARIEC61850

Reusable protocol and transport engine

IEC 61850 frame models, SCL parsing, Sampled Values decoding primitives, PCAP handling, and Npcap transport components.

ARVREL

Virtual relay and engineering workflow

Process-bus orchestration, measurement windows, trust policy, protection elements, relay faceplate, operator workflow, evidence, and export.

Project model

Core logic remains outside the WPF render cadence.

Arvrel.ProcessBus

Live/replay sources, stream discovery, SCL binding, decoding, sample rings, RMS, phasors, continuity, trust, and immutable evidence models.

Arvrel.Protection

Deterministic protection elements, timers, direction, trip latch, operation records, and algorithm-policy behavior independent from WPF refresh.

Arvrel.App

Windows operator shell, waveform and phasor instruments, relay LCD, settings workflow, event presentation, persistence, and export.

Threading and state

Capture, replay, evaluation, and presentation have different lifecycles.

Background work

  • Npcap capture runs outside the UI dispatcher through a bounded transport channel.
  • PCAP replay runs on a worker task.
  • Per-stream mutable rings and protection state are guarded privately.
  • Protection is evaluated when decoded ASDUs arrive, not when WPF renders.

Operator presentation

  • The UI requests immutable snapshots at a bounded cadence.
  • Complete two-cycle evidence windows feed waveform presentation.
  • The newest complete one-cycle window feeds protection RMS and phasors.
  • Last coherent evidence can remain visible while unhealthy live data recovers.
Design intent: UI responsiveness must not define protection timing, and diagnostic visibility must not silently become trip authority.

Known boundary

Architecture supports engineering evaluation, not certified real-time protection.

  • Outputs remain virtual only.
  • No calibrated measurement or IEC 60255 type-test claim is made.
  • Windows, Npcap, adapter drivers, publisher behavior, and host load influence live performance.
  • Generic SCL layouts use the reusable engine; inferred fixed layouts must remain clearly identified.
  • Custom algorithm source remains shadow-only.
