Reproducibility matrix

Trace every scenario to an exact automated test.

The catalog below separates measurement checks, operate cases, secure or restrained cases, and trust-blocked cases. Each scenario has a stable identifier, expected outcome, source implementation, test file, and test method.

Open machine-readable catalogRun laboratory exercises

Evidence levels

Not all green tests support the same claim.

Measure

Numerical result

A deterministic fixture checks a calculated RMS, phase, sequence, or residual quantity.

Operate

Expected virtual operation

Pickup, delay, trust permission, and operation conditions produce a virtual trip.

Restrain

Expected security

Normal load, reverse direction, unavailable evidence, or another non-operate condition remains secure.

Block

Trust-based restraint

Protection activity can remain visible while the current evidence prevents a new virtual trip.

Run locally

Use exact project and test filters.

The protection tests do not require a live adapter or customer data. Use a clean source checkout and record the ARVREL commit, .NET SDK, operating system, and test output.

dotnet test .\tests\Arvrel.Protection.Tests\Arvrel.Protection.Tests.csproj -c Release

dotnet test .\tests\Arvrel.Protection.Tests\Arvrel.Protection.Tests.csproj -c Release `
  --filter "FullyQualifiedName~FundamentalEstimator_ReturnsRmsMagnitudeAndBalancedPositiveSequence"

dotnet test .\tests\Arvrel.Protection.Tests\Arvrel.Protection.Tests.csproj -c Release `
  --filter "FullyQualifiedName~SmvTrustGate_BlocksOperationWithoutHidingPickup"

dotnet test .\tests\Arvrel.Protection.Tests\Arvrel.Protection.Tests.csproj -c Release `
  --filter "FullyQualifiedName~DirectionalPhase67_TripsForwardAndRestrainsReverse"

Traceability rule

The public catalog is checked in CI.

The public-site validator verifies the scenario schema, unique identifiers, current version, allowed outcomes, referenced source and test files, and presence of every named test method. A broken source-to-test link fails the public-site gate.

Inspect validatorInspect site CI

Interpretation boundary

This matrix is not a product certification report.

It documents deterministic software fixtures and source traceability. It does not replace independent model validation, calibrated injection, timing instrumentation, communication-stress testing, hardware-in-the-loop testing, IEC 60255 type testing, IEC 61850 conformance testing, cybersecurity assessment, or site acceptance.
