Gate-based maturity

Advance capability only when the evidence is ready.

ARVREL's roadmap uses entry and exit criteria rather than promotional dates. A feature becomes public only when source, settings identity, operate and secure tests, trust behavior, evidence output, documentation, and safety boundaries are all defined.

Research track A

Signal-estimator robustness and characterization.

Strengthen the current nominal-frequency baseline before broader accuracy or timing claims.

Entry criteria

  • Stable synthetic waveform fixture generator
  • Versioned expected-value tolerances
  • CPU and allocation measurement method
  • Documented nominal-frequency assumptions

Exit criteria

  • 45–55 Hz and 55–65 Hz frequency sweeps
  • Harmonic, interharmonic, noise, and quantization fixtures
  • Decaying-DC and CT-saturation cases
  • Window and estimator comparison report
  • Operate and secure impact analysis for all enabled functions
Until complete: ARVREL should continue to describe the current method as a nominal-frequency one-cycle single-bin DFT, not a general FFT analyzer or calibrated phasor measurement unit.

Research track B

87T transformer differential protection.

87T is a planned research track, not an implemented public-beta function. It will not be added as a UI label before multi-stream measurement, compensation, security, and evidence requirements are met.

Public-entry gate: 87T requires paired internal-fault operate and through-fault/inrush/saturation secure cases, not only a successful trip demonstration.

Research track C

Deployment-oriented virtualization and timing benchmarks.

This track investigates concepts associated with lightweight or virtual protective relays while preserving a strict boundary from the current Windows laboratory product.

Candidate research environment

  • Linux real-time or another deterministic host profile
  • CPU affinity and isolation
  • Bounded memory allocation
  • Process priority and scheduling policy
  • Independent traffic and timing instrumentation
  • Fault containment and restart behavior

Required metrics

  • Frame ingress-to-measurement latency
  • Measurement-to-pickup latency
  • Pickup-to-operation latency
  • Worst-case and percentile jitter
  • Loss, burst, load, and contention sensitivity
  • Recovery and failover time
No inherited claim: implementing CPU affinity or running in a virtual machine would not by itself justify calling ARVREL deployment-grade or hard real time. The timing contract, instrumentation, workload, and failure model must be published.

Research track D

Independent and hardware-in-the-loop validation.

Stage 1

Software fixtures

Expand deterministic unit and integration tests, scenario catalogs, and source-to-test traceability.

Stage 2

PCAP and publisher replay

Use sanitized captures and controlled publishers for continuity, quality, identity, scaling, and timing stress.

Stage 3

HIL comparison

Use calibrated sources and independent timestamping to compare quantities, operate times, restraint, and recovery.

Certification boundary: even a successful internal HIL campaign is not automatically IEC 60255 type testing or IEC 61850 conformance certification.

Deferred functions

Visible backlog without false availability.

46, 47, 49, 81U/O, 32, 37, 50BF, 79, 25, 86, 74TCS, 60, negative-sequence 67N polarization, and memory polarization remain deferred. Their presence on this roadmap does not imply implementation, release timing, or suitability.
