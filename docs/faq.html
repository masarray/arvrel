Engineering FAQ

What to know before evaluating ARVREL.

Clear answers about product scope, signal sources, protection coverage, trust and evidence, safety, privacy, source development, and licensing.

Product scope

What ARVREL is—and is not.

What is ARVREL?

ARVREL is a vendor-neutral Windows laboratory that turns IEC 61850 Sampled Values or internally generated signals into measurements, virtual protection decisions, and reviewable engineering evidence.

Is ARVREL a real protection relay?

No. It provides a virtual relay model and virtual trip latch for laboratory evaluation. It has no physical relay contacts, operational GOOSE trip, MMS control, autonomous switching, or switching authority.

Is it a calibrated relay test set?

No. Internal virtual injection is intended for software laboratory scenarios. It is not calibrated test equipment and does not produce IEC 60255 type-test or commissioning-acceptance evidence.

Is it hard real time?

No. ARVREL runs on Windows and does not claim deterministic hard-real-time scheduling, deployment-grade virtual-IED availability, or guaranteed operational trip timing.

Signal sources

Internal, replay, and live evaluation.

Can I evaluate ARVREL without an SV publisher?

Yes. `v0.1.0-beta.1` includes a deterministic internal A-G scenario. The current development line adds an editable 4I+4V Virtual Injection Laboratory; it becomes an official packaged capability only after a release tag includes it.

Can ARVREL replay captures?

Yes. ARVREL supports controlled PCAP and PCAPNG replay so stream behavior can be reviewed without connecting to a live process-bus network.

What is required for live capture?

Npcap must be installed separately, and the selected Windows network adapter must support the authorized laboratory capture. Live capture should be performed only on isolated networks with explicit permission.

Does ARVREL use SCL?

Yes. SCL context can support stream identity, APPID, address, dataset, svID, confRev, channel mapping, and scaling review. Trust depends on the available evidence and configured context.

Protection and measurement

What is currently implemented.

Which protection functions are available?

The public implementation covers virtual 50P-1, 51P, 50N, 51N, 67P, 67N, 27, 59, and 59N. Individual feeder elements default to disabled until explicitly configured.

Does ARVREL implement transformer differential 87T?

No. 87T is a research track with explicit entry criteria for multi-stream alignment, transformer and CT compensation, biased differential logic, inrush and CT-saturation security, trust behavior, and paired operate/secure validation.

How are phasors estimated?

The current fundamental estimator uses a complete one-cycle, arithmetic-mean-removed, nominal-frequency single-bin DFT scaled to a complex RMS phasor. It is not a full harmonic-spectrum FFT or adaptive frequency tracker.

What happens to duplicate or out-of-order frames?

They remain visible in telemetry, but their payload samples are rejected before entering RMS, waveform, phasor, or protection buffers. Trust state determines whether measurement, pickup, and virtual-trip authority remain available.

Trust and evidence

How ARVREL explains a decision.

What does “trust before trip” mean?

ARVREL separates AllowsMeasurement, AllowsPickup, and AllowsTrip. A stream may remain diagnostically visible while communication, identity, mapping, scaling, quality, or continuity evidence blocks new protection authority.

What evidence can be reviewed?

Evidence can include source identity, trust state, active settings and fingerprints, measured quantities, pickup and trip timestamps, operated element, phase or earth cause, event trace, and export metadata.

Are research claims reproducible?

Public scenarios use stable IDs mapped to exact source files, test files, and named automated test methods. The validation page publishes expected measurement, operate, restrain, and trust-blocked outcomes.

Does a passing software test prove field suitability?

No. Software tests support code behavior and reproducibility. They are not calibration, conformance, type-test, commissioning-acceptance, or operational-availability evidence.

Installation and development

Packages, dependencies, and support.

Should I use the installer or portable package?

Use the installer for normal Windows evaluation and the portable ZIP when installation is restricted. In both cases, download from GitHub Releases and verify the published SHA-256 checksum.

What is required to build from source?

Windows 10/11 x64, .NET 8 SDK, Git, and the sibling ARIEC61850 repository at the commit pinned by the release workflow. Npcap is needed only for live capture.

Where should issues be reported?

Use the GitHub issue templates and include the ARVREL version, operating mode, reproduction steps, expected and actual behavior, relevant logs, and only non-confidential fixtures.

Can I request commercial support?

Yes. Public support and GPL use remain available, while separate commercial terms may be negotiated for proprietary redistribution, OEM deployment, closed-source integration, or contractual support.

Privacy and licensing

Use engineering data responsibly.

Where does ARVREL store local data?

Local preferences and diagnostics are stored under %LOCALAPPDATA%\ARVREL. Review logs and exported evidence before sharing them.

What data should never be published?

Do not publish customer captures, proprietary station SCL files, credentials, IP plans, employer-confidential information, or data that you are not authorized to disclose.

What license applies?

The source is licensed under GPL-3.0-or-later. Third-party components retain their own licenses. See the repository license and third-party notices for obligations.

Where can I find the complete documentation?

Use the documentation hub for user, workflow, architecture, protection, research, release, security, contribution, and public-site maintenance guides.

Responsible evaluation

Start internally, then move outward deliberately.

Begin with a deterministic internal scenario, continue with controlled replay, and use live capture only on an isolated, authorized laboratory network. Do not use ARVREL as the sole basis for operational settings, commissioning acceptance, or switching decisions.
