# Supply-chain security

ARVREL release and CI workflows apply layered controls to reduce dependency and artifact risk.

Current public release: **v0.1.0-beta.6**.

## Automated controls

- Dependabot checks NuGet packages and GitHub Actions weekly.
- CodeQL scans the C# codebase on pull requests, pushes to `main`, and a weekly schedule.
- CI and release builds use an immutable pinned ARIEC61850 engine commit.
- Every third-party GitHub Action is pinned to a full commit SHA.
- Release build jobs use read-only repository access.
- Only the isolated publication job receives `contents: write`, `attestations: write`, and `id-token: write`.
- Release assets receive GitHub build-provenance attestations.
- When a CycloneDX SBOM is generated, the installer and portable package also receive SBOM attestations.
- NuGet vulnerability auditing remains a blocking CI and release gate.

The beta.6 release pins:

```text
masarray/ARIEC61850
0d0aa4e31c17f9e5a10901ad52fa75e9c4581daf
```

## Verify the current official release

Download the selected beta.6 release asset and `SHA256SUMS.txt` from the same GitHub Release, then verify locally:

```powershell
Get-FileHash .\ARVREL-Setup-v0.1.0-beta.6-win-x64.exe -Algorithm SHA256
Get-FileHash .\ARVREL-v0.1.0-beta.6-win-x64-portable.exe -Algorithm SHA256
Get-FileHash .\ARVREL-v0.1.0-beta.6-win-x64-portable.zip -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

Every locally calculated hash must exactly match the corresponding release entry.

Verify GitHub build provenance with the GitHub CLI when desired:

```powershell
gh attestation verify .\ARVREL-Setup-v0.1.0-beta.6-win-x64.exe --repo masarray/arvrel
gh attestation verify .\ARVREL-v0.1.0-beta.6-win-x64-portable.exe --repo masarray/arvrel
gh attestation verify .\ARVREL-v0.1.0-beta.6-win-x64-portable.zip --repo masarray/arvrel
```

Use the exact versioned filenames from the selected release if checking a future version.

## Signing boundary

Community beta.6 binaries are not claimed as Authenticode-signed. Checksums, SBOMs, and provenance attestations improve integrity and traceability but do not bypass Windows reputation controls, AppLocker/WDAC, endpoint policy, or organization software-approval procedures.

## Trust boundary

Attestations establish which GitHub repository, commit, workflow, and build event produced an artifact. They do not make ARVREL a calibrated relay test set, certified protection IED, manufacturer-specific relay clone, IEC 61850 conformance result, IEC 60255 type-test result, commissioning-acceptance instrument, or source of operational switching authority.

For the full product/status boundary see [`CURRENT_STATUS.md`](CURRENT_STATUS.md) and the public [Release status](https://masarray.github.io/arvrel/release-status.html).
